# 第二版五任务多 LoRA 路由预实验：结果交接

整理日期：2026-10-18（北京时间）。范围：`experiments/v2-routing` 的 0.6B、seed42、五任务小集；目标模型 Qwen3-8B BF16，L=8，单张 RTX 6000D。本文件记录已经完成的实测与预注册停止决定，**不是完整多 seed 或云边实验报告**。第一版数据、权重与 gate 保持冻结。

## 一句话结论

五个专家存在**事后可见的接受质量互补**，但现有 prompt 路由和反馈路由没有把它转化为比同数据混合 LoRA 更好的净时延。按远端 `experiments/v2-routing/program.md` 第 2 节预注册的 P3 gate 停止，P4 扩量、多 seed 和最终测试未解锁。该结果否定的是**当前预实验配置与实现的加速主张**，并不证明多专家路由在任何优化实现或边云系统中都不可行。

## 我们的质量与路由结果

以下为 `adapter_val` 的 L=8 公共前缀诊断，单位是每请求合格窗口上的**平均连续接受草稿 token**，不是接受率，也不是在线速度。

| BASE | MIX16 | MIX80 | 已知任务 DOMAIN | 最佳固定专家 | 事后 Oracle |
|---:|---:|---:|---:|---:|---:|
| 3.404 | 3.762 | 3.792 | 3.784 | 3.657 | 4.036 |

Oracle−MIX80 为 **+0.245 token**，请求级配对 bootstrap 95% 区间 **[+0.093, +0.387]**；Oracle−最佳固定专家为 **+0.380**，区间 **[+0.278, +0.493]**。Oracle 事后查看目标输出和所有专家，只量化潜在互补，不能被写作可上线的路由速度。[质量原始汇总](quality_summary.json)

在另外 120 条 `router_val` 上，prompt-only 分类器的任务领域识别为 **100%**，但落入接受最优专家集合的比例为 **75.8%**。其实际选择的平均接受长度 **3.566**，低于同请求 MIX80 的 **3.668**，差 **−0.102 token**。这说明“识别出数据来源领域”不等于“选中目标模型最愿意接受的草稿专家”。远端原始路由汇总：`experiments/v2-routing/results/routing/summary.json`。

## 在线速度和正确性

下表都使用同一批 40 条请求、同设备、同目标 AR8；数值小于 1 表示比直接生成慢。平均接受草稿长度与上一节的 240 条离线矩阵**不是同一统计样本**。

| 方法 | 在线平均每轮接受 token | 速度／AR8，五任务几何平均 | 速度／MIX80 |
|---|---:|---:|---:|
| BASE，原始 0.6B | 3.206 | 0.409 | — |
| MIX16 | 3.303 | 0.368 | — |
| MIX80 | 3.342 | 0.373 | 1.000 |
| DOMAIN，已知任务选择 | 3.300 | 0.356 | — |
| ROUTE-ACC，prompt-only | 3.300 | 0.366 | — |
| META-UCB，受 MetaSD 启发 | 3.285 | 0.364 | 0.974 [0.930, 1.015] |
| COST-UCB，第二版候选 | 3.231 | **0.356** | **0.955 [0.913, 0.990]** |

COST-UCB 相对 AR8 的请求级 bootstrap 95% 区间为 **[0.324, 0.392]**。八种 SD 方法的 320 次请求输出都与 AR8 的完整 token、EOS、截断一致。单卡实现里连 BASE 也慢于 AR8，提示需要拆分草稿生成、目标验证、缓存与 Python 调度开销；目前没有完整组件 CUDA profiling，**不能把慢的原因确定归咎于其中某一项**。[静态在线汇总](online_summary.json) · [反馈路由汇总](feedback_summary.json)

## 限制与后续决策

这只是 seed42 小集、40 条在线请求、一次计时；NQ-Open 不等于完整 Natural Questions，最终 ID／外部集、seed43／44、三次随机顺序计时、4B 五专家和真实 WAN 都未做。不能将“事后 Oracle 有空间”写成“可部署路由有效”，也不能将当前单卡负结果推成所有云边方案不可能加速。

若另开实验，应先用同请求的组件 profiling 查明草稿、目标验证、缓存与调度时延；再在严格逐 token 正确性下比较优化实现和同数据 MIX80。任何新策略或云边／大目标模型扩展要另列协议与基线，不能把此轮 P3 否定结果改写为通过。本轮 GPU 计算进程已核实为零，15 分钟值守已暂停；未经新授权不会自动扩量、推送或发布。
